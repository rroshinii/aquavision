# AquaVision: Intelligent Underwater Object Detection

AI-powered underwater vision for marine monitoring, exploration, conservation and infrastructure inspection.
CS5305 Machine Learning project, Chennai Institute of Technology (R. Roshini, Rakshita).

AquaVision is a full-stack web app built on the project's existing **Ultralytics YOLO11** model:

- **Image detection**: drag-and-drop upload, original vs. annotated result, boxes + labels + confidence
- **Video detection**: frame-by-frame analysis with progress, playable/downloadable annotated video
- **Live detection**: real-time webcam detection in the browser
- **Underwater enhancement**: colour-cast correction, CLAHE contrast, denoise, sharpen (optional toggle)
- **Dashboard**: overview stats, analytics, searchable history (SQLite), CSV/JSON exports, settings
- All numbers shown in the UI are computed from real stored detections. Nothing is hard-coded.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py                    # open http://localhost:5000
```

Use `http://localhost:5000` (not a LAN IP) for the webcam page, since browsers only allow camera access on localhost or HTTPS.
Set `PORT`, `HOST`, `AQUAVISION_DATA` (where uploads/results/DB live) or `AQUAVISION_WEIGHTS` (path to a `.pt` file) as environment variables if needed.

## About the model (please read)

The repository's original weights, `models/yolo11n.pt` and `models/yolo11s.pt`, are the **standard COCO-pretrained YOLO11 models**.
They have 80 everyday classes (person, boat, bird, ...) and **no fish, coral, debris, rock or structure classes**. The original
desktop app (`desktop_app/underwater.py`) kept only `person` detections and labelled them **Diver**. AquaVision preserves exactly that default
(same confidence 0.28, image size 576, same alias set), so out of the box it detects **divers**.

The class list shown in the app is **read from the loaded weights**. To detect marine animals, coral, waste, etc., train on a labelled underwater
dataset and drop the result in. No code changes are needed:

```bash
# 1. Put YOLO-format images/labels in dataset/images/{train,val} and dataset/labels/{train,val}
# 2. List your classes (the dataset/data.yaml is generated by the script)
python scripts/train_yolo.py --dataset-root dataset --classes fish coral debris rock diver --epochs 100
# 3. Use the result
cp runs/train/diver_detector/weights/best.pt models/best.pt
python run.py
```

Weight lookup order: `AQUAVISION_WEIGHTS` -> `models/best.pt` -> `runs/train/diver_detector/weights/best.pt` -> `models/yolo11s.pt` -> `models/yolo11n.pt`.
In **Settings** you can switch "Classes reported" between *Auto* (original diver-only behaviour for COCO weights) and *All classes the model knows*.
The `dataset/` folder is currently empty; `data.yaml` declares one class (`diver`). Public datasets to start from include
[Brackish](https://www.kaggle.com/datasets/aalborguniversity/brackish-dataset), DeepFish and TrashCan (check each license).

## API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/model` | loaded weights, device, reported classes |
| POST | `/api/detect/image` | multipart `file`, optional `enhance`, `confidence` |
| POST | `/api/detect/video` | starts a background job, returns `job_id` |
| GET | `/api/jobs/<id>` | progress, then the finished record |
| POST | `/api/detect/frame` | single webcam frame (not stored) |
| POST | `/api/enhance` | enhanced image preview |
| GET | `/api/stats` | dashboard/analytics aggregates |
| GET/DELETE | `/api/history`, `/api/history/<id>` | history; `export.csv`, `<id>/report.json` |
| GET/POST | `/api/settings` | defaults |

## Notes and limits

- Video counts are **detections summed over analysed frames**; one object visible for 50 frames counts 50 times. This is stated in the UI.
- Video frames wider than 1280 px are downscaled for speed. "Analyse every Nth frame" trades speed for coverage.
- CPU inference works but is slow for video; a CUDA GPU is used automatically when available.
- The H.264 re-encode for in-browser playback uses the ffmpeg bundled with `imageio-ffmpeg`; if it fails, the file is still downloadable.
- Uploads are limited to 500 MB. There is no authentication; run it locally or behind your own access control.
